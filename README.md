## На основе какой работы сделан проект

Проект вырос из интернет-магазина **КР №3 (`kr3-responsive-shop`)**: оттуда взяты
структура страниц, адаптивная вёрстка и визуальный стиль. В КР №4 добавлен слой
интерактивности: товары больше не написаны в HTML, а хранятся в массиве и выводятся
скриптом, появились поиск, фильтры, сортировка, корзина, избранное и валидация формы.

Отличие от предыдущей работы принципиальное: HTML остался «скелетом» страницы,
а всё, что касается данных и поведения, перенесено в папку `js/`.

Скрипты подключаются в конце каждой страницы в одном и том же порядке:

Каждый модуль проверяет, есть ли на странице его элементы, поэтому один и тот же
набор скриптов безопасно работает на всех шести страницах.

## JavaScript-файлы: кто за что отвечает

### `data.js` — данные

Единственный источник товаров. Массив `products` из **11 объектов**. У всех товаров
одинаковый набор полей:

```js
{
  id: 1,                     // уникальный номер
  title: 'Наушники Aura Studio',
  category: 'Аудио',         // совпадает со значением фильтра
  price: 12990,              // число, не строка
  oldPrice: 15990,           // старая цена или null
  isAvailable: true,         // наличие
  rating: 4.8,
  badge: 'Хит',              // бейдж на карточке или null
  image: 'images/headphones.svg',
  shortDescription: '...',   // текст для карточки
  description: '...'         // текст для страницы товара и модального окна
}
```

Почему массив объектов: один товар — одна запись, к полям обращаются по имени,
а добавление нового товара не требует правок в HTML. Одинаковые поля позволяют
писать общий код вывода и не проверять каждый объект на наличие свойств.

### `catalog.js` — каталог и страница товара

- `createProductCard(product)` — собирает карточку: `createElement`, `textContent`,
  `classList`, `append`. Никакой разметки товара в HTML нет.
- `getVisibleProducts()` — поиск + фильтр + «только избранное» + сортировка копии массива.
- `renderCatalog()` — очищает контейнер, заново выводит карточки, обновляет счётчик
  и переключает пустое состояние.
- `fillCategoryFilter()` — строит `option` для категорий из массива, поэтому значения
  в фильтре всегда совпадают с `product.category`.
- `handleProductsClick(event)` — одно delegated-событие на всю сетку: добавление в корзину,
  избранное и быстрый просмотр определяются по `data-action`.
- `initProductPage()` — читает `?id=`, выводит данные товара и похожие товары,
  а при неизвестном id показывает аккуратное «Товар не найден».

### `cart.js` — корзина

- `getCart()` / `saveCart()` — чтение и запись `localStorage` с фильтрацией мусора.
- `addToCart`, `removeFromCart`, `setCartQuantity`, `clearCart` — изменение состояния.
- `getCartDetails()` — собирает позиции и считает суммы, итог через `reduce`.
- `renderCart()` — строки корзины, счётчики, блок итогов, пустое состояние.
- `handlePromoSubmit` — проверка промокода и пересчёт скидки.
- `refreshOrderSummary()` — сводка заказа на странице `order.html`.

### `modal.js` — быстрое просмотр

Разметка окна создаётся один раз через `createElement`: оверлей, диалог, кнопка закрытия,
картинка и текстовые узлы. Данные подставляются через `textContent`. Окно закрывается
кнопкой, кликом по фону и клавишей `Escape`, а фокус возвращается на кнопку, с которой
его открыли.

### `validation.js` — валидация форм

- `orderRules` — правила для имени, e-mail, телефона, города, комментария и согласия.
- `setFieldError` / `clearFieldError` — текст ошибки под полем, класс `field--invalid`,
  `aria-invalid` у поля.
- `initOrderForm()` — проверка при отправке, живая проверка после первой попытки,
  имитация отправки, очистка формы и корзины, номер заявки.
- `initContactsForm()` — те же помощники для формы обратной связи.

### `main.js` — общее

`readStorage` / `writeStorage`, `formatPrice`, `createNode`, `createButton`,
уведомления `showToast`, избранное (`getFavorites`, `toggleFavorite`), тёмная тема,
мобильное меню, счётчики в шапке и активный пункт навигации.

## Что реализовано

### Каталог и карточки

Карточки генерируются в `catalog.js` при загрузке страницы. В HTML для сетки есть
только пустой контейнер:

```html
<div class="product-grid" id="catalog-grid"></div>
```

Порядок работы: найти контейнер → очистить (`replaceChildren`) → пройти по массиву →
создать элементы → заполнить текстом через `textContent` → добавить через `append`.

### Поиск по названию

Поле `#search-input`, событие `input`. Сравнение без учёта регистра:

```js
const matchesSearch = product.title.toLowerCase().includes(searchValue);
```

Результат виден сразу, кнопку «найти» нажимать не нужно. Колбэк не тормозит ввод,
потому что товаров 11 — дебаунс здесь не нужен.

### Фильтрация по категории

`select#category-filter`, событие `change`. Список категорий строится из массива
товаров, а не пишется руками в HTML, поэтому опечатка «Аудио» / «аудио» невозможна.
Опция `all` показывает всё.

### Сортировка

`select#sort-select`, событие `change`. Варианты: по цене (возрастание/убывание)
и по названию (А–Я / Я–А). Сортируется **копия** массива:

```js
const sorted = [...filtered];
sorted.sort((first, second) => first.price - second.price);
```

Исходный массив `products` остаётся в том же порядке — это важно, чтобы фильтры
и повторный сброс работали предсказуемо.

### Пустое состояние и счётчик

Если после фильтров ничего не осталось, сетка скрывается и показывается блок
`#catalog-empty` с объяснением и кнопкой сброса. Над сеткой выводится
«Найдено: N из 11». Кнопок сброса две (в тулбаре и в пустом состоянии), обе
подключены через класс `js-reset-filters`.

### Страница товара

`product.html?id=4` — данные берутся из массива по id, заголовок вкладки меняется
на название товара. Если id нет или он неверный, страница не падает: показывается
сообщение «Товар не найден» и ссылка в каталог.

### Валидация формы заявки

Форма на `order.html` проверяет:

| Поле | Правило |
| --- | --- |
| Имя | не пустое, от 2 до 40 символов |
| Телефон | только цифры, пробелы, скобки, `+`, `-`; от 10 до 15 цифр |
| E-mail | обязателен, проверяется по шаблону `name@mail.ru` |
| Город | необязательно, не длиннее 60 символов |
| Комментарий | необязательно, не длиннее 300 символов |
| Согласие | обязательно |

Пустая форма не проходит проверку: все ошибки появляются одновременно, первое
проблемное поле получает фокус, а общий статус пишет «Проверьте выделенные поля».
После первой попытки отправки поля проверяются на лету, чтобы ошибка исчезала,
как только её исправили. При успехе появляется панель с номером заявки вида
`KR4-123456`, форма очищается, корзина обнуляется. Никаких `alert()`.

### Безопасный вывод данных

Пользовательские и каталожные данные выводятся только через `textContent` или
`createElement(...).textContent`. В проекте **нет ни одного `innerHTML`** — проверить
можно поиском по папке `js/`. Адреса ссылок собираются конкатенацией id, а не
подстановкой пользовательской строки в разметку. Это защищает от XSS: если в
названии товара или в поле формы окажется `<script>`, он будет показан как текст.

### События

Все обработчики подключены в JS через `addEventListener`: `input` (поиск, живая
валидация), `change` (фильтр, сортировка, чекбоксы), `click` (кнопки, делегирование
на сетке), `submit` (обе формы с `preventDefault()`), `keydown` (Escape в модальном
окне). Inline-обработчиков вида `onclick="..."` в HTML нет.

## Самостоятельные доработки

Сверх обязательной части сделано следующее — каждую доработку можно показать отдельно.

### 1. Корзина с сохранением в `localStorage`

Товары хранятся как `[{ id, quantity }]` под ключом `kr4-shop:cart`. После перезагрузки
страницы и перехода между страницами корзина остаётся на месте. Количество меняется
кнопками `−` / `+` (от 1 до 99), товар удаляется отдельной кнопкой, есть полная очистка.

### 2. Расчёт суммы через `reduce`

```js
const subtotal = items.reduce((total, item) => total + item.sum, 0);
const quantity = items.reduce((total, item) => total + item.quantity, 0);
```

Итог пересчитывается после каждого действия и обновляет счётчик в шапке.

### 3. Промокод и скидка

На странице корзины: `SALE10` — минус 10%, `TECH15` — минус 15%. Скидка считается
от суммы товаров, показывается отдельной строкой. Промокод сохраняется в
`localStorage` (`kr4-shop:promo`), переживает перезагрузку, а пустое поле сбрасывает его.
Неизвестный код даёт понятное сообщение об ошибке, а не молчание.

### 4. Избранное

Сердечко на каждой карточке, странице товара и в модальном окне. Список id хранится
в `kr4-shop:favorites`, счётчик — в шапке. В каталоге есть переключатель
«Только избранное», а ссылка с сердечком в шапке открывает `catalog.html?favorites=1`
сразу с включённым фильтром. Кнопки синхронизируются: добавили товар в избранное
в модальном окне — сердечко на карточке тоже стало активным.

### 5. Тёмная тема

Кнопка в шапке переключает `data-theme` на `<html>`, выбор сохраняется в
`kr4-shop:theme`. В `<head>` каждой страницы есть маленький скрипт, который применяет
тему до отрисовки — без вспышки светлого фона. Если тема не выбрана, берётся системная
настройка `prefers-color-scheme`.

### 6. Модальное окно товара

Быстрый просмотр без перехода на другую страницу: картинка, категория, рейтинг,
наличие, цена, описание, кнопка «В корзину» и ссылка на полную страницу. Закрывается
кнопкой, кликом по фону и `Escape`, фокус возвращается туда, где был. Разметка
создаётся скриптом, поэтому не дублируется в шести HTML-файлах.

### 7. Улучшенные карточки и состояния

Бейджи «Хит» / «Новинка» / «Нет в наличии», рейтинг, старая цена, приглушённая
картинка у недоступного товара, заблокированная кнопка добавления. Уведомления
о действиях («товар добавлен в корзину», «промокод применён») всплывают в правом
нижнем углу и озвучиваются скринридером (`role="status"`).

### 8. Завершённый сценарий заявки

Форма заявки связана с корзиной: в сводке справа видно состав заказа, количество,
скидку и итог. После успешной «отправки» заявка получает номер, корзина очищается,
форма сбрасывается, панель успеха получает фокус. Отдельная форма обратной связи
на странице контактов использует те же правила проверки имени и e-mail.

### 9. Доступность и мелочи

`aria-pressed` у сердечек и переключателя темы, `aria-invalid` у полей с ошибкой,
`aria-live` у статусов, скрытые подписи у полей поиска и фильтров, ссылка «Перейти
к содержимому», `prefers-reduced-motion`, адаптивность до 400 px. Счётчики в шапке
и активный пункт меню обновляются на каждой странице.

14. Открыть DevTools → Console на всех страницах: ошибок нет.

## Запуск

Проект статический, сборка не нужна.

**Вариант 1 — просто открыть файл.** Открыть `index.html` двойным кликом. Всё работает,

```bash
python -m http.server 8080

# или Node.js
npx serve .
```

Затем открыть `http://localhost:8080`.

## Что сказать на защите

- `data.js` — данные, остальные файлы — поведение; HTML отвечает только за каркас.
- Карточки создаются в `catalog.js`: `querySelector` → `replaceChildren` → `createElement`
  → `textContent` → `classList` → `append`.
- Поиск слушает `input`, фильтр и сортировка — `change`, формы — `submit`
  с `preventDefault()`.
- `sort()` применяется к копии `[...filtered]`, чтобы не менять исходный массив.
- `textContent` вместо `innerHTML`: данные не могут исполниться как разметка.
- `addEventListener` вместо `onclick`: поведение в JS, один обработчик на сетку
  благодаря делегированию и `data-action`.
- Ошибки формы выводятся в DOM рядом с полями, `alert()` не используется вообще.
- Состояние (корзина, избранное, тема, промокод) живёт в `localStorage`, поэтому
  сценарий не рвётся при переходе между страницами.
